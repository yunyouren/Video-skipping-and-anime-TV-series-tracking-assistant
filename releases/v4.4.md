# v4.4 修复说明

此版本修复 2026-09-16 对 v4.3 审查中确认的核心问题。

- **断点续播**：先核对视频及集数，再恢复播放位置；恢复前不覆盖已有进度。尊重用户手动定位和网站已恢复的位置，避免把上一集的时间带到下一集。
- **收藏独立设置**：分别保存片头、片尾开关、时长、最短时长、启用状态、自动下一集和完播重播。设置区域会注明正在修改哪个收藏。
- **进度可靠性**：收藏更新在后台串行合并；进度写入只更新进度字段，不覆盖同时修改的设置，不重新创建已删除收藏。
- **改名兼容**：保留稳定标识和原名称别名，收藏改名后继续匹配视频并更新进度。
- **统一备份**：弹窗与设置页使用同一格式，可互相导入；兼容旧的纯收藏 JSON 和带 folders/favorites 的旧备份。导入前校验所有记录，格式错误时不写入。
- **嵌套播放器**：首次绑定已加载的视频也会获取父页面信息；下一集按钮在外层页面时可通过后台转发点击。
- **播放结束**：正常结束也能重播；“自动下一集”优先，避免切集同时重播。片尾设为 0 时也能在自然结束后尝试下一集。
- **其他修正**：更新同 URL 下变化的集数信息；恢复首次白名单提示；高级设置改为即时保存；弹窗标题和文件夹按文字显示；修正打包脚本、语言文件及版本说明。

## 验证

- Node.js 回归检查：28 项通过。覆盖恢复位置、开关、切集、重播、iframe、并发保存、删除后迟到的进度、错误恢复、最大集数保护、备份互通、改名、文件夹、模式切换及 HTML 转义。
- 独立 Chromium 153.0.8010.12 中实际加载扩展：9 个流程通过，无页面脚本异常。使用本地可定位的 60 秒媒体资源和嵌套播放器，实际调用浏览器存储与消息接口。
- 浏览器流程包括：续播和首次提示、收藏独立开关、真实媒体跳过、改名后继续保存、跨入口备份恢复、iframe 续播、自然结束重播、外层下一集优先、高级设置自动保存。
- 此验证不等同于 B站、爱奇艺、腾讯等网站逐站兼容性验收。网站按钮结构、广告、付费播放器及特殊集数格式仍需结合具体网站验证。

## 使用新版

解压 v4.4 安装包后，在扩展管理页选择“加载解压缩的扩展”；已从当前源码目录加载的用户，可点击现有扩展的“重新加载”，然后刷新已打开的视频页面。

如果目前用的是商店版本，解压加载会成为另一个扩展实例。请先从旧版导出收藏，在新版导入，再禁用旧版，避免两个版本同时控制视频。

已有收藏和旧备份无需手动转换。同名跨站收藏仍沿用原来的合并行为；本次没有新增新集提醒、更新检测或跨设备自动同步。
